Trinkspiel Battle App

Spontane Bierspiel-Challenges per Standort finden & annehmen

Was ist es?

  • Mobile-first Web App für Bierspiel-Challenges zwischen Gruppen
  • Nutzer posten offene Challenges auf einer Live-Karte
  • Andere nehmen sie an — Gewinner steigen im Leaderboard
  • Crews: Gruppen können zusammen antreten

Hürden & Lösungen

Technische Probleme, auf die wir gestoßen sind — und wie wir sie gelöst haben

Session-Bug
Login verliert Cookie nach Redirect
Next.js Soft-Nav überträgt Supabase-Session-Cookies nicht. Fix: window.location.href statt router.push → Full Page Reload.
Race Condition
Zwei User nehmen dasselbe Match an
DB-Check opponent_id IS NULL im API-Route verhindert Doppel-Accept durch optimistisches Locking.
SSR-Crash
Leaflet Map bricht beim Build
Leaflet braucht window-Objekt. Fix: dynamic import mit ssr: false isoliert es vom Server-Render.
TypeScript-Fehler
Supabase-Joins als Array inferiert
Supabase-Client gibt Joins immer als Array zurück. Fix: as unknown as Type Cast als einheitliches Pattern.
Scope-Entscheidung
Solo-Matchmaking war zu komplex
Queue-basiertes Matchmaking gestrichen → vereinfacht zu reinen Map-Challenges. Klarer und nutzbarer.
Deployment
Vercel CLI im Uni-Netz geblockt
eduroam blockiert die CLI-Auth. Umweg: Deploy via Vercel Browser-UI per GitHub-Import.

Wichtige Architektur-Entscheidungen

  • Server Actions als einzige Mutations-Schicht — kein direkter DB-Zugriff vom Client
  • 5s-Polling statt Supabase Realtime — einfacher, kein Websocket-Overhead
  • OpenStreetMap kostenlos, kein API-Key nötig
  • Leaflet Icons lokal gebündelt — kein CDN-Risiko
